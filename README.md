# SmartBook – Full SRS Demonstration Project

A local, classroom-ready implementation of the 14 SmartBook SRS feature areas. It uses **Node.js + Express + SQLite + HTML/CSS/JavaScript**. It does not require Firebase, a cloud account, or a separate frontend server.

> This is a local academic prototype. It demonstrates the main user workflows and SRS concepts. In-app notifications replace external Firebase push/email delivery; AI recommendations are transparent rule-based ranking; QR access is time-bound and single-use. Production deployment would require HTTPS, managed secrets, hardened authorization, real push/email delivery, and concurrency/load testing.

## Requirements
- Node.js 18 or newer (LTS recommended)
- VS Code
- Internet only for the first `npm install` (to download packages)

## Install and run (Windows PowerShell)
1. Extract this ZIP.
2. Open the extracted `SmartBook_Full_SRS_Demo` folder in VS Code.
3. Open Terminal → New Terminal.
4. Run these commands:

```powershell
node -v
npm -v
npm install
node seed_demo.js
npm start
```

5. Open http://localhost:3000

The SQLite database `smartbook.db`, sample spaces, equipment, and demo accounts are prepared by the seed script. Run `node seed_demo.js` once before the first start. You can run it again safely; it does not duplicate the demo accounts.

To use auto-restart during development:

```powershell
npm run dev
```

## Theme Preferences (System, Light, Dark)
SmartBook includes a persistent, real-time theme selector accessible from the top header on any page, the login screen, and the Preferences tab:
- **System (Default):** Automatically detects and tracks your operating system's color mode (Light or Dark) dynamically without requiring a page reload.
- **Light:** Applies an elegant pastel peach and warm neutral color palette (#FAF3ED background, #F7D9CC soft peach, #FFFDFC cards, #4A3832 text, and #D9785D muted terracotta accents).
- **Dark:** Applies a complementary warm charcoal and dark brown theme (#211C1A background, #302622 secondary, #392F2B cards, #F7EDE7 warm off-white text, and #E8A58F soft peach accents).

User preferences are saved persistently to `localStorage` (`sb_theme_preference`).

## Demo accounts
The seed script creates the demo accounts. If you have already run it during setup, you do not need to run it again. To recreate/check the accounts later, stop the server and run:

```powershell
node seed_demo.js
```

- Admin: `admin@smartbook.demo` / `Admin@123`
- Faculty: `faculty@smartbook.demo` / `Faculty@123`
- Student: `student@smartbook.demo` / `Student@123`

Register additional Student or Faculty accounts from the login screen. Admin accounts are not publicly self-registered.

## Recommended teacher demonstration order
1. Login as Student. Find a room, filter by date/time/capacity, see suggestions, and book a room.
2. Select a large venue (Auditorium/Amphitheatre) to demonstrate a Pending approval request.
3. Login as Faculty or Admin in another browser/incognito window and approve/decline the request. Login as the student again to see the notification.
4. Book a room with equipment IDs (see Equipment page) and group members to demonstrate combined room/equipment booking.
5. Show the booking QR pass. Login as Faculty/Admin and verify the QR token during the booking time window. Verification is single-use.
6. Attempt an occupied room/time and join the waitlist. Cancel the existing booking as its owner. The next eligible waitlisted user receives an in-app offer. Accept/decline it before expiry.
7. Use Quick Book to reserve a currently free space for a short duration.
8. Login as Faculty and add a recurring lecture/lab block.
9. Login as Admin. Add/deactivate a space, manage equipment, set maintenance dates, and inspect affected bookings/notifications.
10. Open Priority Reports and export CSV. Change waitlist offer duration / active booking limit in System Settings.
11. Open Notifications and Preferences. Reminder notifications are generated by a scheduled job approximately 15 minutes before a booking.

## Important QR demo note
QR verification is accepted only during the booking's actual date/time and only once. For an easy classroom demonstration, create a booking for the current date and a time window that includes the current time. The QR can then be scanned/read by staff; the demo UI shows the QR image. Verification API accepts the decoded token.

1. Stop the server with Ctrl+C.
2. Delete `smartbook.db`.
3. Run `node seed_demo.js`.
4. Run `npm start`.

## API overview
- `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`
- `GET/POST/PUT/DELETE /api/rooms`
- `GET /api/recommendations`, `POST /api/quick-book`
- `GET/POST/PUT/DELETE /api/bookings`, `GET /api/bookings/:id/qr`
- `POST /api/qr/verify`
- `GET/POST /api/waitlist`, `POST /api/waitlist/:id/accept`, `POST /api/waitlist/:id/decline`
- `GET/POST/PUT/DELETE /api/equipment`
- `GET/POST /api/maintenance`
- `GET/POST /api/faculty/blocks`
- `GET /api/approvals`, `POST /api/approvals/:id`
- `GET /api/notifications`, `PUT /api/notifications/:id/read`, `PUT /api/preferences`
- `GET /api/reports/priority`, `GET /api/reports/priority.csv`
- `GET/PUT /api/settings`, `GET /api/dashboard`

Protected APIs require `Authorization: Bearer <token>`. The frontend adds this automatically after login.
